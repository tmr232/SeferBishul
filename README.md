# Sefer Bishul

## תגיות וניווט

אפשר לשייך מתכון לכמה תגיות בעזרת חזית YAML בתחילת קובץ המתכון:

```markdown
---
תגיות:
  - טיגון עמוק
  - חנוכה
---
# סופגניות

## חומרים
...

## הכנה
...
```

אפשר גם לכתוב `תגיות: [טיגון עמוק, חנוכה]`. שמות התגיות חייבים להיות
מחרוזות לא ריקות; רווחים בקצוות ותגיות כפולות מנוקים בבנייה.
מתכונים ללא חזית או ללא תגיות ממשיכים לעבוד כרגיל.

הבנייה יוצרת את `tags.html`: מסך תגיות בשתי עמודות, עם קישור לכל
המתכונים המשויכים לכל תגית. הצבע של כל תגית נקבע מהשם שלה ונשאר קבוע
גם כשמוסיפים תגיות אחרות, ללא תלות בדפדפן או במכשיר. הכתובות נקבעות לפי
מזהי התגיות המתוארים בהמשך.
קישורים לתגיות מופיעים בתוכן העניינים, בגלריה ובמתכונים עצמם.
הקטגוריה של כל מתכון לפי התיקייה שלו נכללת אוטומטית גם כתגית, בנוסף לתגיות
שבחזית המתכון. בתיקיות מקוננות משתמשים בנתיב היחסי המלא, כמו בתוכן העניינים
(למשל `חגים/חנוכה`). אם אותה תגית מופיעה גם בחזית, היא נכללת פעם אחת בלבד.
מתכונים בתיקיית `recipes` עצמה לא מקבלים תגית תיקייה.
החלוקה הקיימת לקטגוריות בתוכן העניינים נשארת ללא שינוי.

## מזהים וכתובות קצרות

מתכונים נבנים בכתובות `r/<slug>.html`. ברירת המחדל היא תעתיק ASCII של
כותרת המתכון באמצעות `python-slugify`, ולא של שם הקובץ או התיקייה.
למשל, הכותרת `לחם` יוצרת `r/lkhm.html`. כדי לקבוע כתובת נוחה וקבועה,
מוסיפים שדה `מזהה` לחזית המתכון:

```yaml
---
מזהה: olive-bread
תגיות: [אפייה]
---
```

הכתובת תהיה `r/olive-bread.html` גם לאחר שינוי הכותרת או העברת הקובץ
לתיקייה אחרת. ללא מזהה מפורש, שינוי כותרת עשוי לשנות את הכתובת.
המזהים חייבים להיות מחרוזות לא ריקות של אותיות לטיניות קטנות, ספרות
ומקפים בודדים בין מילים. מזהה לא תקין או מזהי מתכונים כפולים מכשילים את
הבנייה עם פרטים על המקור; אין הוספה אוטומטית של מספרים לפתרון התנגשויות.

כתובות התגיות הן `tags/<slug>.html`. הקובץ `tag-slugs.yaml`, ליד תיקיית
`recipes`, ממפה שמות תגיות למזהים שניתן לערוך ידנית. הוא כולל גם תגיות
מהחזית וגם קטגוריות המבוססות על תיקיות, כולל נתיבים מקוננים מלאים.
ליצירה ולעדכון שלו מריצים:

```sh
uv run --locked update-tag-slugs recipes
```

הפקודה מוסיפה תגיות חדשות לפי `python-slugify`, שומרת מזהים שכבר קיימים
ואינה מוחקת תגיות שהוסרו, כדי לא למחזר כתובות בטעות. למשל, אפשר לתת
למפתח `חגים/חנוכה` את הערך `hanukkah`. הבנייה הרגילה קוראת את הקובץ אך
אינה משנה אותו; לתגית שעדיין לא מופיעה בו משתמשים בברירת המחדל.
גם מזהי תגיות כפולים מכשילים את הבנייה ואת פקודת העדכון, כולל התנגשות
בין ברירת מחדל למזהה ידני. אפשר להשתמש באותו מזהה למתכון ולתגית, משום
שהם בתיקיות שונות. לקובץ מיפוי במקום אחר אפשר להשתמש ב־`--tag-slugs PATH`
גם בפקודת הבנייה וגם בפקודת העדכון.

כל קישורי הניווט, החיפוש, השיתוף וה־Open Graph משתמשים בכתובות החדשות.
לא נוצרות הפניות מהכתובות העבריות הישנות או מכתובות התגיות הקודמות;
לאחר פרסום בנייה נקייה הן יציגו את דף ה־404. הקטגוריות והשמות המוצגים
באתר נשארים בעברית.

## חיפוש מתכונים

העמוד `search.html` מאפשר חיפוש בדפדפן בכל המתכון, בשם בלבד, בחומרים או
בהוראות ההכנה. כמה מילים מחפשות יחד (כולן חייבות להופיע בתחום שנבחר),
ללא תלות בניקוד. החיפוש הוא התאמת טקסט, לא ניתוח לשוני.
אפשר לשתף את כתובת החיפוש ולחזור לתוצאות עם כפתור החזרה בדפדפן.
הבנייה יוצרת `search-index.json` מתוך אותם אסימוני Markdown ומכונת מצבים
שמשמשים להצגת המתכון: כותרת משנה ראשונה לחומרים, שנייה והלאה להכנה.
אין פענוח Markdown בדפדפן ואין צורך בשירות חיפוש.

## פיתוח

נדרשים Python 3.15.2, uv 0.13.8 ו־Bun 1.4.4. גרסאות Python ו־Bun
מוגדרות גם בקבצים `.python-version` ו־`.bun-version`.

באורב חדש, `.agents/setup` מתקין את הגרסאות האלה ואת התלויות הנעולות
אוטומטית. אפשר להריץ אותו גם ידנית; הרצה חוזרת משתמשת בהתקנות ובמטמון הקיימים.

```sh
uv sync --locked
bun install --frozen-lockfile
uv run --locked nox -s lint test build
```

לעיצוב הקוד: `uv run --locked nox -s format`. Ruff מעצב ובודק את קוד
Python, ו־mypy בודק טיפוסים. Biome אחראי רק לעיצוב JavaScript ו־JSON;
oxlint אחראי לבדיקות JavaScript, ללא כללי עיצוב מתחרים. בדיקות JavaScript
בתיקיית `tests` רצות באמצעות Bun, כולל קובצי `.test.mjs`.

תלויות Python נעולות ב־`uv.lock`, ותלויות כלי JavaScript ב־`bun.lock`.
לאחר שינוי תלויות מריצים `uv lock --upgrade` או `bun update` בהתאמה.
תלויות GitHub Actions, כולל תלויות עקיפות, נעולות ב־`.github/workflows/actions.lock`.
לאחר שינוי workflow מעדכנים ומוודאים את הנעילה:

```sh
gh extension install github/gh-actions-lock --pin v0.4.1
gh actions-lock
gh actions-lock --verify
```

האתר נוצר בתיקיית `public`. אפשר להגיש אותה באמצעות שרת קבצים סטטי;
הניווט בתגיות אינו דורש JavaScript או שרת יישום.

## התקנה כאפליקציה

אפשר להתקין את [ספר המתכונים](https://cookbook.baharschwarz.com/)
לגישה ממסך הבית. ההתקנה פותחת את תוכן העניינים בחלון עצמאי בדפדפנים
תומכים; כל המתכונים ודפי התגיות נכללים בתחום האפליקציה.

אם האפליקציה הותקנה מהכתובת הישנה `https://tmr232.github.io/SeferBishul/`,
יש להתקין אותה מחדש מהכתובת המאובטחת החדשה, לבדוק שהיא פועלת ואז להסיר
את ההתקנה הישנה. ההפניה מהאתר הישן אינה מעבירה את זהות האפליקציה,
את תחום הכתובות שלה, את ההרשאות או את נתוני האתר לכתובת החדשה.

- באנדרואיד: פותחים בכרום ובוחרים באפשרות ההתקנה בתפריט הדפדפן.
  האפשרות והניסוח משתנים לפי הדפדפן והמכשיר; בחלקם מתקבל קיצור דרך בלבד.
- באייפון ובאייפד: פותחים בספארי, בוחרים שיתוף ואז ״הוסף למסך הבית״.
  אם מוצג המתג ״פתח כיישום אינטרנט״, משאירים אותו פעיל.
  אין חלונית התקנה אוטומטית כמו בחלק מדפדפני כרומיום.
- במחשב: כרום ואדג׳ תומכים בהתקנה מתפריט הדפדפן; בספארי במק
  נתמך אפשר לבחור ״הוסף ל־Dock״. בדפדפנים אחרים התמיכה משתנה,
  ואין להניח שתופיע אפשרות להתקנת אפליקציה.

נדרש חיבור לאינטרנט לקריאת המתכונים גם לאחר ההתקנה. לא נוסף מטמון
לשימוש לא מקוון, ולא נרשם עובד שירות. אין הבטחה להצגת כרזת התקנה אוטומטית;
אפשר להשתמש בתפריט הדפדפן כאשר הוא תומך בכך.

הבנייה מעתיקה את המניפסט והסמלים מתוך `src/sefer_bishul/static`.
הקישורים יחסיים, כולל מתוך מתכונים בתיקיות מקוננות, כך שאותה בנייה מתאימה
גם לאירוח הנוכחי בשורש האתר וגם לאירוח בנתיב משנה, כמו `/SeferBishul/`.
יש להגיש את האתר בחיבור מאובטח; בפיתוח מקומי אפשר להשתמש בשרת מקומי.

## שיתוף וקישורים חיצוניים

בכל מתכון מופיע קישור ״שיתוף״ לצד קישורי הניווט שמעל הכותרת. לחיצה רגילה
פותחת את השיתוף המובנה של המכשיר בדפדפנים תומכים ובחיבור מאובטח.
אם השיתוף אינו נתמך או נכשל, נעשה ניסיון להעתיק את הקישור ומוצגת הודעה.
הודעות השיתוף נעלמות לאחר חמש שניות; ניסיון נוסף מאפס את הזמן להודעה החדשה.
ביטול השיתוף אינו מעתיק דבר. אם ההעתקה אינה זמינה, מופיעה הנחיה להעתיק
דרך לחיצה ארוכה או תפריט הלחצן הימני. זהו קישור אמיתי לכתובת המתכון:
תפריט הקישור והעתקתו זמינים גם ללא JavaScript, ולחיצות עם מקשי שינוי
ממשיכות לפעול כרגיל. התמיכה בלחיצה ארוכה תלויה בדפדפן ובמערכת ההפעלה.

למתכונים נוצרות תגיות Open Graph ב־HTML עצמו, כך שרובוטי תצוגה מקדימה
אינם צריכים להריץ JavaScript: כותרת, תקציר טקסט, כתובת ותמונת המתכון.
למתכון ללא תמונה משמש סמל האפליקציה הקיים. כתובות השיתוף והתמונות הן
מוחלטות ומקודדות; כתובת המתכון משתמשת במזהה הקצר, ושמות תמונות יכולים
להישאר בעברית. ברירת המחדל היא האתר
`https://cookbook.baharschwarz.com/`; באירוח אחר יש לבנות עם
`build-book recipes images public --site-url https://example.com/cookbook/`.
אין לשנות זאת לכתובת שרת פיתוח אם רוצים לשתף קישורים לאתר הציבורי.
התצוגה בפועל והמטמון שלה נקבעים על ידי שירות השיתוף, ויש לבדוק אותם לאחר פרסום.

קישורי HTTP(S) בתוכן המתכונים שמחוץ לתחום ספר המתכונים מקבלים
`target="_blank"` ו־`rel="noopener noreferrer"`, גם אם הם לאתר אחר באותו
דומיין. ניווט בתוך הספר נשאר באותו חלון. זה מבקש לפתוח הקשר גלישה נפרד,
אך אינו מבטיח פתיחה בדפדפן ברירת המחדל: במחשב מותקן הוא עשוי לפתוח
חלון דפדפן, ובאנדרואיד וב־iOS ייתכן דפדפן בתוך האפליקציה. מערכת ההפעלה
והדפדפן שולטים בכך; אין API אינטרנטי נייד שמכריח פתיחה בדפדפן חיצוני מסוים.
ראו [מגבלות חלונות ב־PWA](https://web.dev/learn/pwa/windows)
ו[תמיכה בשיתוף מובנה](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share).
